# 書き方注釈仕様

版: `annotation-spec-0.1-step53`<br>
入力版: `confirmed-0.3-step46-all132`<br>
対象: 非公開作業データ/文章詳細化/対象132件.jsonl の基礎本文132件<br>
状態: STEP53で定義した注釈契約。投稿ごとの観測結果はSTEP54～56で記録する。

## 1. 目的と分析範囲

この仕様は、保存済み本文を同じ単位・基準で読み、P01～P05の具体的な書き方ルールへ根拠を渡すためのものです。対象132件は全件を分析し、反応条件がmatchの24件とunknownの108件は記述上の内訳として持ちます。反応状態、旧型への適合、本文の長短、絵文字の有無、文章の良し悪しを理由に除外・重み付けしません。どの項目でも判断できない記録を削除せず、当該項目の`unknown`として残します。

本文の文言、商品情報、価格、投稿者の実体験、販促条件の真偽は、観測された表示だけでは独立に検証できません。注釈が示すのは本文中の表現・配置・論理の観測です。いいね等との共起を、投稿文の効果、拡散や売上の因果、再現保証とは呼びません。

## 2. 分析用テキストと位置参照

1. 本文ファイルを原記録とし、原文は変更しません。解析上の改行だけCRLF/CRからLFへ正規化した作業表現を使います。空白・句読点・絵文字・タグの削除や整形は行いません。
2. 各レコードの主キーは`source_id`（Bで始まる既存観測ID）です。出典には対象一覧の`body_ref`と元のJSONL参照を残します。
3. 根拠位置は`line_no`（1始まり）、`unit_kind`、同じ行・種別内の`unit_no`（1始まり）で示します。例: `line_no=3, unit_kind=sentence, unit_no=2`。同じ一文が複数機能を持つ場合は同じ位置参照を共有し、文を機能数だけ複製しません。
4. `excerpt`は所在を特定するために必要な短い連続部分だけを非公開注釈へ保存します。説明のため全文を重複保存しません。公開成果では短い抜粋と匿名IDに限ります。
5. 元本文全体を読めない場合は対象IDを維持し、その理由を記録して該当項目を`unknown`にします。132件の分母を減らさず、判読不能が生じた工程は計画の完了条件に従って未完了とします。

## 3. 注釈単位

| 単位 | 定義と分割方法 | 二重計数の防止 |
| --- | --- | --- |
| 投稿 | `source_id`に対応する保存本文全体。本文ファイル1件を1投稿レコードとする | 投稿レベルの有無は1投稿につき1回だけ数える |
| 行 | LFで区切られた物理行。先頭・末尾空白は内容から削らず、空行も位置として残す | 改行は文の境界とは限らない。行数と文数を混ぜない |
| 段落 | 1行以上の非空行が連なったまとまり。1行以上の空行で次段落へ移る | 空行の連続を複数段落として水増ししない |
| 文 | 終止の`。！？!?`で区切られる独立した文。終止記号はその文に含める | 省略記号・URL内記号・小数点・製品型番のピリオドでは分けない |
| 文片 | 句点がなくても、行末やタグ前に独立した見出し・体言止め・短い呼びかけとして置かれた表現 | 文と文片を別々に数える場合、同じ文字範囲を両方の出現数へ加えない |
| 節 | 一つの述語を中心とする意味単位。逆接・理由・条件・並列などで二つの命題が独立するとき分割する | `、`があるだけでは分割しない。節の根拠位置は親文を併記する |
| タグ | `#`から始まり、空白・改行または明確な終端句読点まで続く表示文字列。URLの`#fragment`は除く | 同じタグが反復すれば出現数は複数、異なり数は1。本文中と末尾を別欄で保持する |
| 絵文字 | Unicode拡張書記素クラスタとして一つに表示される絵文字列（ZWJ連結、肌色修飾、国旗、キーキャップ、異体字セレクタを含む） | 結合された列は表示単位1。隣接した別絵文字はそれぞれ数える。符号位置数と混同しない |
| 顔文字 | 顔・感情を表す複数の文字・記号の組合せ。Unicode絵文字クラスタとは別区分 | 文字数、絵文字数に含めず、顔文字出現として数える |
| 記号 | 箇条書き記号、矢印、装飾括弧、強調記号など。絵文字・顔文字ではない文字 | 役割（列挙・誘導・装飾・強調）を別注釈し、絵文字として加算しない |

**短文の扱い:** 見出しだけの行、句点なしの一言、タグへつなぐ断片は`文片`として保持します。複数の述語が連なる一文は終止記号で一文と数えつつ、論理注釈では独立命題の節へ分けます。疑問符・感嘆符の連続は一つの終端として扱い、記号の反復数は別の表記特徴として記録します。

## 4. 全15観点の判定契約

各観点は投稿単位の状態を一つ持ち、`labels`に複数の観測分類を付けられます。同じ箇所へ複数役割を付けることはできますが、同一ラベルの同一箇所を重複登録しません。判断の根拠位置と理由を必ず関連づけます。

| ID・観点 | `present`として記録するもの | 数えないもの／注意 |
| --- | --- | --- |
| A01 冒頭の引き | 最初の非空行・意味単位が、読者呼びかけ、課題、疑問、驚き、季節、販促、体験の提示、結論先出し等で注意を向ける場合。複数の機能があれば複数ラベル | 先頭にあるだけの商品名・型番を自動的に「引き」としない。実際に読者を引き付ける効果を測ったとはしない |
| A02 読者と語り手 | 想定読者の明示語、読者への二人称、語り手の一人称・集合的主語、省略主語、敬体・常体・口語の選択を観察 | 一人称表現を本人の実体験の証明としない。読み手の属性や性別を推定しない |
| A03 文・節・段落の役割 | 商品参照、特徴・仕様、根拠、便益、使用場面、感情、体験主張、注意・留保、販促、案内、タグの各役割と順序 | 役割語句の単純検索だけで機能を決めない。役割のない語を無理に分類しない |
| A04 論理展開 | 同じ文・隣接単位の命題関係（特徴→便益、課題→対応、理由→結論、対比、譲歩、条件→提案、具体→要約、列挙等） | 接続語の存在と関係の意味を別々に記録する。「だから」「ので」があっても因果の正しさは検証しない |
| A05 情報と感情の流れ | 事実表現と評価・感情が現れる順、強調・具体化・利用場面・案内への移行 | 絵文字や強い形容だけから読者の感情変化・購買効果を推定しない |
| A06 構文 | 主語・述語、修飾、短文連鎖、疑問、命令・依頼、体言止め、倒置、対句、引用、括弧、箇条書き等の形 | 語順が近いだけで同じ修辞と決めない。省略主語を推測で補わない |
| A07 言い回し・定型表現 | 呼びかけ、つなぎ、評価、便益、具体化、留保、案内の語句を短い機能スロットに抽象化する | 原文の特徴的な文言を規則テンプレートへ転載しない。単発表現から定型性を断定しない |
| A08 語尾とリズム | 敬体・常体、断定・推量・疑問・感嘆・名詞止め、文末の組合せ、短長の変化、反復を記録 | 絵文字や句読点の個数だけで読みやすさ・リズムの優位を評価しない |
| A09 語彙と表記 | 具体名詞、数値・単位、形容詞、擬音・擬態語、比喩、口語、略語、強調表記、全半角等 | 投稿内の主張を事実確認済みと扱わない。健康・美容・安全等の効能を生成事実に転用しない |
| A10 絵文字・顔文字 | 種類、表示クラスタ数、位置（冒頭・文中・文末・箇条書き・案内・タグ周辺）、連続、反復、本文との意味的関係 | 複合絵文字を符号位置数で数えない。顔文字・文字記号・箇条書きを絵文字にしない。役割を曖昧に感じたらunknown |
| A11 見た目と読みやすさ | 改行・空行、段落、行頭見出し、箇条書き、区切り記号、本文とタグの境界、行あたり文字量を記述 | 客観的な構造記述と主観的な読みやすさ評価を分ける。固定の最適行長・絵文字密度を設定しない |
| A12 数値・販促・社会的証明 | 価格、割合、期間、数量、順位、口コミ、人気、限定等の表現、対象条件の記載、出典を示す語の有無 | 現在の価格・期間・在庫・ランキング・人気・口コミの真偽を投稿文から認定しない。見えない出典を補わない |
| A13 終結と案内 | 末尾の要約、対象者への提案、閲覧・検索案内、質問、注意、タグへの移行、案内なしの閉じ方 | 一般的な評価語だけを自動的にCTAとしない。末尾タグがあるだけで本文の結論があるとしない |
| A14 タグとの接続 | タグの意味群、本文との関連が明示されるか、本文内/末尾の位置、本文文への埋込み、重複、タグへの移行 | タグから本文にない仕様・対象者・使用体験を追加推測しない。URL fragmentはタグにしない |
| A15 境界・例外 | 複数型の混在、特徴不足、短文・長文、絵文字なし、論理飛躍、過度の販促、体験留保、誤認を誘い得る表現を具体的位置とともに記録 | 1投稿を既存5型のどれかに無理に押し込まない。問題らしさだけで投稿者の意図・虚偽を断定しない |

### 根拠区分

- `observation`: 本文に実際に見える語句・順序・記号・改行・単位数。
- `interpretation`: その表現が担う機能、論理関係、語りの働きという注釈者の判定。理由と根拠位置を持つ。
- `design_recommendation`: 将来生成に採用する条件付きの提案。出現頻度から自動的に必須化しない。

実投稿者が自称する体験は`observed_experience_claim`と記録できますが、真実性は`actual_author_experience_verified=false`を維持します。数値や販促も`observed_claim`であり、商品ページ等で確認済みという意味ではありません。

## 5. 状態、ラベル、判断理由

各観点の`status`は以下から一つ選びます。

| 値 | 意味 | 使い方 |
| --- | --- | --- |
| `present` | 全文に一つ以上の根拠があり、観点が確認できた | `labels`と`evidence`に最低1件を記録 |
| `absent` | 全文を確認したが、その観点の特徴が見当たらない | `labels=[]`、検索範囲と確認理由を記録。数え上げで0とは同義でない |
| `unknown` | 見える範囲はあるが、機能・意味・出典・境界を決められない | 不明理由、判断に足りない情報、該当位置（特定できる場合）を記録 |
| `not_applicable` | 観点が論理的に当てはまらない場合 | 理由が必要。単に情報がない場合は`absent`、曖昧な場合は`unknown`にする |

各ラベルには`label_id`、短い定義、`evidence[]`、`rationale`、`evidence_class`を付けます。根拠は`line_no/unit_kind/unit_no`と短い非公開`excerpt`で位置づけます。`absent`には本文全体を走査したことを示す`scan_scope=whole_body`と簡潔な理由を記録します。`unknown`では欠けた根拠・情報を文章化し、値をなし/0へ置き換えません。

理由コード例: `ambiguous_function`（機能が複数に読める）、`source_not_shown`（数値・評価の出典が表示されない）、`fragment_without_context`（断片の前後がない）、`author_claim_unverified`（体験主張の真偽は未検証）、`encoding_or_boundary_unclear`（文字・タグ・絵文字の境界が不明）。コード以外の具体説明も併記します。

## 6. 主型、補助特徴、残余、再分類

1. 対象一覧にある旧構造候補と旧型内nは入力時の基準値として保持し、原記録を上書きしません。
2. 旧構造候補の132件分布は、P01相当の商品参照＋特徴41、P02相当の商品参照＋関連タグ36、P03相当の販促先行23、P04相当の特徴箇条書き15、P05相当の体験＋留保5、タグを含む他役割6、混合・未分類6です。残余12件を5型へ配り直して合計を合わせません。
3. 全体の詳細注釈では、本文内で共起する複数の役割・技法を補助特徴として複数付与できます。主たる論理構成を一つ決められないときは`mixed_or_unclassified`を保持します。
4. 既存のP01～P05定義から外れると判断して再分類する場合は、`old_pattern`、`proposed_detailed_pattern`、`reclassification_status`（`retained`/`overlap`/`reconsidered`/`unresolved`）、対象ID、根拠位置、変更理由を記録します。分布の都合だけで変更しません。
5. 各型内ルールの分母はその型に実際に属する観測ID数、全体ルールの分母は132です。該当型のnと全体n=132を並べ、少数型や残余を全型に見られたように記述しません。

## 7. 注釈ファイル契約

STEP54～56の各JSONLは1行1観測ID、全132行で、`source_id`を一意に持ちます。投稿を項目や文の数だけ複製しません。各レコードに対象一覧への参照、`denominator=132`、反応条件（説明用のみ）、旧型候補、各観点の状態、根拠位置、注釈者の理由を含めます。元本文や投稿者対応表を公開成果へ置きません。

| ファイル | 主に所有する観点 | 注記 |
| --- | --- | --- |
| `論理構成注釈.jsonl` | A01～A05、A12～A15 | 各文・節の機能、論理関係、型・例外、販促主張とタグの本文関係 |
| `表現構文注釈.jsonl` | A02、A06～A09、A13 | A02/A13の意味的役割は論理構成表を参照し、ここでは形態・語尾・定型表現を記録 |
| `絵文字配置注釈.jsonl` | A10～A11、A14の見た目上の位置情報 | A14の本文意味との関連判定は論理構成表が所有し、位置・並びだけを追加 |

共通フィールド: `source_id`, `denominator`, `target_ref`, `body_ref`, `legacy_pattern`, `condition_status`, `reaction_condition_used_as_filter=false`, `annotation_spec_version`, `aspects`, `unreadable_reason`, `annotated_at`（実際に保存する時刻が得られない場合は推定せずnull）。各`aspects`項目は`status`, `labels`, `evidence`, `rationale`, `evidence_class`, `not_applicable_reason`を持ちます。

文・節・絵文字等の単位ごとの注釈は`units[]`へ別記し、各ユニットの一意な`unit_ref`を持たせます。同一ユニットへ複数ラベルを付ける場合も、ラベル別出現数とユニット数を分離します。ファイル間で同じ位置を参照しても、全体集計では観点所有表に従い一度だけ数えます。

## 8. 集計規則

1. 投稿レベルの各観点について`present/absent/unknown/not_applicable`をそれぞれ件数で出し、全体の母数132を併記します。unknownやnot_applicableを除いた比率を出す場合は、その分母と除外状態件数を明記し、全132件分析と並べます。
2. 投稿における有無と投稿内の出現数を分けます。`post_n`は各投稿を最大1回、`occurrence_n`は単位別の出現数、`unit_n`は分析した文/節/行等の数です。これらを合算しません。
3. 複数回答項目ではラベル件数の合計が132を超える場合があります。その場合は複数ラベルであることを表示し、排他的構成比として扱いません。
4. 型別比較は旧型内nを使い、全体母数132を併記します。残余12件（旧候補6＋混合/未分類6）を削らず、独立した比較群・境界例として示します。
5. 共起は「同じ投稿に両方が観測された件数」または「同じユニットに共存した件数」と定義し、どちらかを明示します。反応状態別内訳を出す場合も記述のみで、除外・重み付け・成功率としません。
6. 欠測・曖昧は行として残し、項目別に数えます。項目判定のunknownを全投稿から引いて母数を減らしません。
7. 132件の観測頻度は、読者の注意・共感・購入・反応の因果を証明しません。頻度の高い言い回しをそのまま定型句・必須条件にせず、STEP58以降で安全性・入力条件・設計推奨を別途論証します。

## 9. STEP54～56での適用チェック

- 各ファイルのレコード数132、`source_id`重複0、対象一覧とのID差0を確認する。
- 各対象行に全所有観点が一つずつあり、`present`には根拠、`absent`には全文走査、`unknown`には理由があることを確認する。
- 位置参照が本文中に存在し、抜粋が必要最小限であることを確認する。位置が特定できない主張は`unknown`へ修正する。
- 状態件数の合計、ラベル件数、単位出現数、投稿数の意味を区別する。多重ラベルを排他的割合として扱わない。
- `reaction_condition_used_as_filter=false`を132件すべてで確認し、match24/unknown108以外を理由に含有状態を変えない。
- 観測・解釈・設計推奨の混同、体験・数値・販促の真偽断定、本文全文の公開混入を見つけたら該当工程を直す。

このSTEP53では判定方法を定義しただけで、132件の新しい観測分布、好成績の理由、必須の言い回し、最適な絵文字数・字数はまだ確定していません。
