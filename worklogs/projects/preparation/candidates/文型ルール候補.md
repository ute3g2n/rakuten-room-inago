## 全文作成に共通するルール

1. 1商品につき、コピーして使える新しい本文を1案作る。複数案からの選択は求めない。
2. 商品名・カテゴリ、仕様、価格、キャンペーン、利用場面などは、入力資料で確認できる範囲だけを書く。分からない点は省き、推測で埋めない。
3. 他者の投稿文や特徴的な言い回しを転用せず、候補の構造だけを使って新しい表現にする。
4. 本人が申告していない購入・利用体験、効果、人気順位、割引期間、在庫などを作らない。本人の体験を示す型は、本人が実際に申告した場合だけ使う。
5. 未確認の商品情報、本文長さ、タグ数、型からの軽微な逸脱を理由に商品・完成本文を保留しない。利用できない情報は省略するか、事実を必要としない別の型に切り替える。
6. 価格など変化する情報を文中に使う場合は、与えられた確認値・時点・出典がある場合に限る。確認できなければ販促表現を省く。
7. 商品情報不足や文型の選択は、商品事実の再確認・追加の品質承認・日次ジョブを起動する条件にしない。空本文や生成エラーの処理はこの提案の範囲外で、要件定義側が定める。

## 候補型と使い方

### P01 商品参照＋特徴説明（n=41/132）

- 組立て順: 商品またはカテゴリを示す → 確認できる特徴・仕様を一つ述べる → 必要なら確認済みの場面または根拠のある便益 → 任意の案内・関連タグ。
- 型の核: 対象となる商品またはカテゴリと、少なくとも一つの確認済み特徴を説明する。特徴の裏付けが見つからない場合は作らず、P02の短い構成へ切り替える。
- 入力として使えるもの: 商品名・カテゴリ、確かめられた仕様や特徴、実際の利用場面、本人が希望する表現。
- 適用: 30テーマ候補全体に使える一般型。実際に使える特徴情報の有無で選ぶ。
- 試作例（全て記入欄で、事実の主張ではない）: 「[商品カテゴリ]は[確認済みの特徴]に対応しています。[確認済みの利用場面]に合わせて選ぶ際の参考に。」

### P02 商品参照＋関連タグ（n=36/132）

- 組立て順: 商品またはカテゴリを簡潔に示す → 入力にある確認済みの事実か利用場面を一つ添える → 必要な場合だけ関連タグ。
- 型の核: 誤認のない商品またはカテゴリの記載。追加仕様が不明でも、確認済みの情報だけで短くまとめる。タグで事実を補完しない。
- 入力として使えるもの: 商品名・カテゴリ、確認済みの事実または本文にある利用場面、関連タグ候補。
- 適用: 30テーマ候補全体に使える簡潔型。確認済み情報が少ない場合の基本形。
- 試作例: 「[商品カテゴリ]。[確認できる事実または利用場面]。[関連が確認できた場合だけ #商品カテゴリ #利用場面]」

### P03 確認済み販促情報を先に置く（n=23/132）

- 組立て順: 現時点で確認された販促条件を示す → 対象商品を示す → 確認済みの特徴か利用場面を添える → 任意の案内・関連タグ。
- 型の核: 投稿時点で確認できる販促情報と対象商品。期間、対象、条件が分からない・古い場合は販促表現を省き、P01またはP02へ切り替える。確認不足を商品保留へつなげない。
- 入力として使えるもの: 価格・割引・期間・対象条件の出典と確認時点、対象商品、確認済み特徴。
- 適用: 30テーマ候補全体で条件付き。現在有効と確かめられる販促情報が入力にある場合だけ。
- 試作例: 「[確認済みの期間・条件]の対象は[商品カテゴリ]です。[確認済みの特徴]。」

### P04 確認済み特徴の箇条書き（n=15/132）

- 組立て順: 商品または一行導入 → 独立した確認済み特徴を一項目ずつ並べる → 必要なら利用場面・案内 → 任意の関連タグ。
- 型の核: 水増しにならない複数の異なる確認済み事実があること。一つしか使える事実がない場合は、箇条書きに増やさずP01またはP02へ切り替える。
- 入力として使えるもの: 別々に説明できる2点以上の仕様・特徴、商品またはカテゴリ。
- 適用: 30テーマ候補全体で条件付き。情報を項目別に読む価値があるときだけ。
- 試作例: 「[商品カテゴリ]の確認できる点：\n・[確認済みの特徴A]\n・[確認済みの特徴B]」

### P05 本人の実体験＋留保（n=5/132）

- 組立て順: 本人が実際に経験した条件 → 本人の観察した感想 → 必要な留保・個人差 → 確認できる商品特徴・関連タグ。
- 型の核: 本人が実際に申告した経験と、その経験の範囲に沿う表現。体験申告がなければ一人称や効果を作らず、P01またはP02へ切り替える。体験がないことだけで商品を保留しない。
- 入力として使えるもの: 本人が申告した購入・使用の有無、条件、観察した感想、本人が述べた限界。
- 適用: 30テーマ候補全体で条件付き。本人の実体験が入力で確認できる場合だけ。n=5のため専用のテーマ別ルールは作らない。
- 試作例: 「[本人が申告した使用条件]では[本人が観察した内容]でした。[本人が述べた条件や限界]。」

## 書く順序

1. 読者・利用場面、または選ぶときの問いをひとつ置く。
2. 確認できた商品特徴・使い方を具体的に示す。
3. どの人・用途に合いそうかを条件つきで説明する。
4. 必要な注意・例外や、商品ページで確認すべき点を書く。
5. 押しつけない案内を置き、関連タグを末尾にまとめる。

## 型の選び方

- 場面と特徴を説明したい: 利用場面→特徴→選ぶ人→案内。
- 実体験を伝える: 経験→実感の範囲→注意点→問い。一人称・購入・使用期間は本人の入力にある場合のみ。
- 季節・贈答: 場面→商品の確認済み特徴→選ぶ前の確認→案内。
- 情報が少ない商品: 短い評価または要点→根拠→関連タグ。情報がなければ創作で補わない。

## 長さ・タグ

- 本文150～300コードポイント、タグ5～12個は、採用判断前の**任意の参考値**。
- 読みやすさと事実の十分さを優先し、機械的な最低・最大文字数やタグ数を設けない。
- タグは本文に関連する語に限定する。タグ数を反応や成果の予測値にしない。

## 入力・安全条件

- 商品リンクと商品事実の対象が一致していること。
- 価格、在庫、キャンペーン、仕様など変わり得る情報は確認時点を記録する。
- 身体効果、疾病予防、治療、購入体験、人気・順位を無根拠に補わない。
- 商品同一性の確認は重複候補や名称の曖昧なカードへ絞り、すべての本文取得の前提にしない。
- 商品重複を除いた商品数と、本文を取得した投稿数を別々に報告する。

## 候補型と使い方

### P01 商品参照＋特徴説明（n=41/132）

- 組立て順: 商品またはカテゴリを示す → 確認できる特徴・仕様を一つ述べる → 必要なら確認済みの場面または根拠のある便益 → 任意の案内・関連タグ。

- 入力として使えるもの: 商品名・カテゴリ、確かめられた仕様や特徴、実際の利用場面、本人が希望する表現。
- 適用: 30テーマ候補全体に使える一般型。実際に使える特徴情報の有無で選ぶ。
- 試作例（全て記入欄で、事実の主張ではない）: 「[商品カテゴリ]は[確認済みの特徴]に対応しています。[確認済みの利用場面]に合わせて選ぶ際の参考に。」

### P02 商品参照＋関連タグ（n=36/132）

- 組立て順: 商品またはカテゴリを簡潔に示す → 入力にある確認済みの事実か利用場面を一つ添える → 必要な場合だけ関連タグ。
- 型の核: 誤認のない商品またはカテゴリの記載。追加仕様が不明でも、確認済みの情報だけで短くまとめる。タグで事実を補完しない。
- 入力として使えるもの: 商品名・カテゴリ、確認済みの事実または本文にある利用場面、関連タグ候補。
- 適用: 30テーマ候補全体に使える簡潔型。確認済み情報が少ない場合の基本形。
- 試作例: 「[商品カテゴリ]。[確認できる事実または利用場面]。[関連が確認できた場合だけ #商品カテゴリ #利用場面]」

### P03 確認済み販促情報を先に置く（n=23/132）

- 組立て順: 現時点で確認された販促条件を示す → 対象商品を示す → 確認済みの特徴か利用場面を添える → 任意の案内・関連タグ。
- 型の核: 投稿時点で確認できる販促情報と対象商品。期間、対象、条件が分からない・古い場合は販促表現を省き、P01またはP02へ切り替える。確認不足を商品保留へつなげない。
- 入力として使えるもの: 価格・割引・期間・対象条件の出典と確認時点、対象商品、確認済み特徴。
- 適用: 30テーマ候補全体で条件付き。現在有効と確かめられる販促情報が入力にある場合だけ。
- 試作例: 「[確認済みの期間・条件]の対象は[商品カテゴリ]です。[確認済みの特徴]。」

### P04 確認済み特徴の箇条書き（n=15/132）

- 組立て順: 商品または一行導入 → 独立した確認済み特徴を一項目ずつ並べる → 必要なら利用場面・案内 → 任意の関連タグ。
- 型の核: 水増しにならない複数の異なる確認済み事実があること。一つしか使える事実がない場合は、箇条書きに増やさずP01またはP02へ切り替える。
- 入力として使えるもの: 別々に説明できる2点以上の仕様・特徴、商品またはカテゴリ。
- 適用: 30テーマ候補全体で条件付き。情報を項目別に読む価値があるときだけ。
- 試作例: 「[商品カテゴリ]の確認できる点：\n・[確認済みの特徴A]\n・[確認済みの特徴B]」

### P05 本人の実体験＋留保（n=5/132）

- 組立て順: 本人が実際に経験した条件 → 本人の観察した感想 → 必要な留保・個人差 → 確認できる商品特徴・関連タグ。
- 型の核: 本人が実際に申告した経験と、その経験の範囲に沿う表現。体験申告がなければ一人称や効果を作らず、P01またはP02へ切り替える。体験がないことだけで商品を保留しない。
- 入力として使えるもの: 本人が申告した購入・使用の有無、条件、観察した感想、本人が述べた限界。
- 適用: 30テーマ候補全体で条件付き。本人の実体験が入力で確認できる場合だけ。n=5のため専用のテーマ別ルールは作らない。
- 試作例: 「[本人が申告した使用条件]では[本人が観察した内容]でした。[本人が述べた条件や限界]。」
