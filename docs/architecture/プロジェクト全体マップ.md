# プロジェクト全体マップ

この文書は、リポジトリ内で「何がどこにあるか」を探すための案内です。要件や動作の正本ではありません。各システムの仕様はリンク先の仕様書、実際の処理はソースコードを確認してください。

## システムの全体像

このリポジトリには、楽天ROOMの日次運用を支援する処理と、日次障害などを扱う保守処理があります。日次処理は候補商品の調査、紹介文の下書き、日次結果の保存・確認を扱います。保守処理は障害の受付、調査、修正・試験、レビュー、反映、報告を扱います。

~~~mermaid
flowchart LR
    TS[Windows タスク スケジューラ] --> DailyXML[日次タスク定義]
    DailyXML --> CLI[CLI]
    CLI --> Daily[日次パイプライン]
    Daily --> Sources[ROOM / Trends 等の情報源]
    Daily --> AI[AI実行・紹介文生成]
    Daily --> State[SQLite・証拠・トレース]
    Daily --> Views[履歴・ダッシュボード出力]
    Human[本人の投稿結果・報告] --> HumanAPI[Human API / 取込]
    HumanAPI --> State

    TS --> MaintXML[保守 Worker / Watchdog 定義]
    MaintXML --> MaintCLI[保守 CLI・Worker]
    MaintCLI --> Maint[保守工程・担当skill]
    Maint --> MaintState[保守DB・診断ログ・成果物]
    Maint --> Release[反映・障害報告]
~~~

図は主要な境界を示す概略です。正確な要件・例外・入出力は[要件定義書](../specifications/inago/イナゴスキル要件定義書.html)、[日次トレース・ログ一覧](../operations/日次タスクのトレース・ログ出力一覧.md)、[保守フロー構成案](保守フロー_skill直列構成案_2026-10-20.html)を参照してください。

## 試験：tests_inago/

- **test_step*.py**, **test_step21_*.py**〜**test_step24_*.py**：段階別の日次・製品機能試験。
- **test_daily_*.py**, **test_daily_fix_*.py**, **test_acceptance.py**, **test_release.py**：日次pipeline、個別不具合修正、受入・反映境界の試験。
- **test_maintenance_*.py**：保守DB、worker、担当工程、調査、修正、試験、レビュー、反映、報告の試験。
- **conftest.py**, **fixtures*.py**, **fixtures/**, **maintenance_*_support.py**：pytest共通設定、隔離fixture、保守試験ヘルパー。
- **config/**, **live-*_cases.json**：試験ケース用設定・入力。実データや本番実行記録と混同しない。

試験コマンド、対象node、期待値は該当計画または試験記録で確認してください。試験結果の保存先は主に**worklogs/**です。

## ローカル状態・秘密情報

- **.venv-inago/**、**node_modules/**、**__pycache__/**、**.pytest_cache/**、**.pytest-tmp/**、**.coverage**は環境・キャッシュ・試験生成物です。**.pytest-tmp/**は存在しない場合もあります。
- **rakuten-room-inago/runtime/**、**rakuten-room-inago/backups/**は.gitignore対象の本番日次状態とバックアップです。削除・初期化・試験データ置換の前に利用状況を確認してください。
- **非公開作業データ/**と認証ファイルは非公開データです。内容を通常の報告やREADMEへ転記しないでください。
- **worklogs/**はGit管理されている作業記録を含みます。保持要否は各計画・参照台帳・証拠との関係を確認して判断してください。
