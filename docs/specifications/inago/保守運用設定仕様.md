# 保守運用設定仕様

仕様版：1.0（2026-10-17 JST）
要件正本：イナゴスキル要件定義書HTML 2.20 §27.17、AT-MAINT-01、実行計画M §7。
状態：設計値を確定。管理DB・CLI・設定ファイルへの実装はU05以降で行い、配置・保存schema・実適用値は該当STEPで確認する。

本仕様は日次イナゴ処理とは別の保守・障害対応基盤の初期運用値を定める。値を採用するのは計画されたmaintenance処理だけで、既存日次のtimeout/retry/保持値へ一括適用しない。

## 実行と排他

| 設定 | 確定値 | 適用規則 |
|---|---:|---|
| 対象タイムゾーン | `Asia/Tokyo` | `target_date`はJST暦日。対象日、実行/採取/受付/作成/反映時刻を分離する。 |
| 日次開始 | 13:00 JST | 既存の日次開始条件を維持する。 |
| 日次とmaintenanceの全体終了期限 | なし | 17:45/18:00等のrun-wide deadlineを設定しない。 |
| Windows Task Schedulerの日次 `ExecutionTimeLimit` | `PT0S` | 登録済み値をテンプレートと照合する。実行中のtaskは変更せず保留する。 |
| 同時コード修正案件 | 1件 | 追加案件は状態を保持して待機する。 |
| lease heartbeat | 30秒 | 所有者、lease、worker状態を永続管理する。PIDのみで解除しない。 |
| watchdog確認間隔 | 60秒 | 起動未確認・通知欠落・途中終了を補完する。所有者確認前にprocessを停止しない。 |
| 1 AI jobのtimeout | 20分 | 個別jobの上限。遅延応答をtimeout後に採用しない。 |
| 個別request/job取消確認 | 60秒 | 対象IDを確認する。確認できなければ当該runの後続を止め、状態を記録する。 |
| 通信一時失敗retry | 初回に加え最大2回 | retry回数は再試行数。`Retry-After`およびより厳しい既存上限を優先する。恒久失敗はretryしない。 |
| 各レビューの差し戻し | 最大3巡 | 3巡後も未解決なら保留し、指摘と再開条件を保持する。 |
| 1案件の再開 | 初回開始後、最大3回 | 既存のincident/check/attemptを再利用し、新規重複案件へ置き換えない。 |
| 次の日次との優先 | 次の日次を優先 | 調査・隔離試験は継続できるが、本番反映は日次/API切替との排他が成立するまで待機する。 |

## ログと証拠の保持

| 対象 | 確定値 | 適用規則 |
|---|---:|---|
| maintenance JSONL | 90日 | maintenance専用schema/保存先。既存L01～L05・M01/M02等の保持を変更しない。 |
| JSONL 1ファイル | 4 MiB | 上限前にrotateし、ファイル単位で期限を管理する。 |
| JSONL 1日あたり | 20ファイル | 到達後に監査必須eventを書けない場合、記録欠落を隠して進めず、反映・gateを保留する。 |
| 採取証拠のコピー | 原本に期限があればその期限まで。それ以外は採取後90日 | 元期限、採取時刻、取得不能・失効理由を索引へ保持する。既存原本の保持規則は変更しない。 |
| 公開可能な伏字済み計画・報告・レビュー | Git履歴に保持 | 秘密、認証値、商品/投稿本文、個人情報を含めない。 |

ログにはstage/status、許可済みID、件数、safe error code/class、相関ID、版、参照だけを記録する。prompt、AI応答本文、URL、query、DOM、認証情報、任意自由文を記録しない。書込失敗・quota到達・保全不能は成功へ読み替えない。

## 正常日から復旧まで

日次のCLI最終結果、工程trace、export、preservation/end backupを照合してからcheckを確定する。正常または根拠のある正常不足ならcheckのみで終了し、異常/未知だけをincident工程へ渡す。日次全体の17:45/18:00終了時刻を再導入しない。

基盤releaseは要件・構成・レビュー・凍結必須テスト・必要な実接続・Git追跡先・実起動設定の一致がそろうまで `ready` にしない。10/17の遡及案件はready後に限る。source runが存在しない場合 `source_run_id=null` を使い、元の日次結果を変更しない。

## 実装で確定する項目

U05以降でstorage path、DB schema/version、具体的なfield名、status enum、CLI名、timeout/retryのtransport実装を確定する。この仕様版の運用値を変更する必要が生じた場合は、根拠・影響・要件/辞書/trace/受入への反映を記録し、独立レビューを通す。
