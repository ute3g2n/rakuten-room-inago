構成案・未実装 ／ 2026年10月23日

商品検索 → 投稿文作成 → 画像削除

選別した15商品のHTMLと画像内の文字を、投稿文作成の入力に追加する。

既存処理に必要な部分だけ追加。
検索・選別の条件、テーマ配分、投稿文の文型・出力形式、失敗時の扱いは従来どおり。以下の5工程を対象とする。

5工程の流れ

1

商品検索時に、HTMLと画像を保存

従来の商品ページ遷移時に、次の3要素を追加取得する。

span.sale_desc span.normal_reserve_item_name span.normal_reserve_catch_copy
  • 描画後DOMの outerHTML を、本文・属性を含めて全文保存する。該当要素が複数あれば全件保存する。
  • span.sale_desc 内の全画像を保存する。遅延読込・画像候補・背景画像も確認し、商品内の同一URLは1ファイルにまとめて出現順を残す。
  • 商品単位のフォルダへ、HTML・取得記録・画像データを格納する。取得日時、画像URL、保存先、取得状態も記録する。
↓
2

投稿文を作成する商品を選別

  • 従来と同じ規則で選別し、作成対象の商品一覧を実行IDに結び付けて保存する。
  • 選別されなかった商品は、[1]の追加取得フォルダを丸ごと削除する。同じ実行ですでに選別済みの商品は保持する。
↓
15件に満たない間は繰り返す
従来どおりTrends検索 → 商品検索 → 選別。初回は選別済み15件がそろったら[3]へ進む。
↓
3

全取得画像をOCRし、商品別JSONへ変換

  • 選別済み15商品の保存画像を、全件OCRする。画像の用途や認識scoreによる事前選別は行わない。
  • 検証済みの PaddleOCR／PP-OCRv6 medium・日本語・CPU を使用する。既存Python処理から呼び、モデルを一度読み込んで順に処理する。
  • 商品ごとに ocr.json を作成。画像順に ref / status / text を保存し、OCR全文と改行を維持する。

動作確認済み：PaddleOCR 3.7.0、PaddlePaddle 3.3.1、oneDNN無効。5商品59画像でOCRとJSON変換・全文一致を確認済み。検証処理のロジックを本番用の保存先へ組み込む。

↓
4

従来入力 ＋ HTML ＋ OCR全文で投稿文を作成

1商品ずつ、ファイルの内容を読み込んで既存のAI入力に追加する。

input_payload
├─ 従来の offer / purpose / facts / author_experience
├─ product_page_html  ← 3要素のHTML全文
└─ product_page_ocr   ← ocr.jsonの全画像分のOCR結果

全入力を参照して、従来の文型・執筆ルールで投稿文を作成する。HTML要素・OCR画像の参照IDも既存の入力参照へ登録し、AIは使った参照IDを従来どおり返す。

投稿文作成AIへ加える指示

OCRでの抽出テキスト内の改行は画像のレイアウトを反映しています。改行を単語や文の区切りと決めつけず、前後の行も文脈に含めて読んでください。英数字が改行をまたぐ場合も、自然につながると判断できるときだけ一語として解釈し、不確かな箇所は推測で補わないでください。

既存の商品情報と照らし、対象商品に結び付く説明を使ってください。発送・配送案内、店舗案内、操作用の文字、別商品など、投稿本文に不要な文章は除外してください。商品に関係するかの判断は、この投稿文作成の中で行ってください。

HTMLとOCRの本文は商品資料として扱う。追加のAI分類・事前要約工程は設けず、OCRテキストも切り詰めない。

↓
5

投稿文の保存完了後、画像を削除

  • その商品の投稿文が正常に保存されたら、images/ を削除する。15商品の完了を待たず、商品ごとに削除する。
  • page.json と ocr.json は、入力確認・再生成用に保持する。元画像URL・参照ID・画像の削除結果も記録する。
  • 作成途中・失敗した商品の画像は再開用に保持する。保存済み投稿文に対する削除の未実施・失敗は、再開時にも再試行する。

保存先は、実行ごと・商品ごとに1フォルダ

rakuten-room-inago/runtime/product-page-inputs/
└─ {run_id}/
   └─ shop-{店舗ID}/
      └─ item-{商品ID}/
         ├─ page.json   … 3要素のHTML全文・取得記録・画像一覧
         ├─ images/     … span.sale_desc 内の全取得画像
         │  ├─ 001.jpg
         │  └─ 002.png …
         └─ ocr.json    … 全画像のOCR結果（商品ごとに1ファイル）

既存の商品識別子 店舗ID:商品ID を使用する。店舗IDも階層に入れ、別店舗の同じ商品IDを区別する。ID中のパスに使えない文字は符号化し、元のIDは page.json に残す。

page.json のHTMLはセレクターごとの配列で保持。要素の「なし」「空」「取得失敗」を区別する。ocr.json は既存の提案形式を使い、画像ごとの success / empty / error を保持する。参照IDには実行IDと商品識別子を含め、商品間・実行間で衝突させない。

タイミング商品フォルダの扱い
選別されなかった商品フォルダ全体を削除
投稿文を正常に保存したimages/ を削除。HTML・OCR JSONは保持
作成途中・失敗再開に必要なデータを保持

既存処理への組み込みは3か所

既存の処理追加・変更すること
商品ページ取得商品ページを閉じる・検索画面へ戻る前に、HTMLと画像を保存する。
Pythonの実行制御選別済み一覧を既存の再開情報に追加。選別後すぐの投稿文作成を、15件の確保 → OCR・変換 → 投稿文作成の順へ移し、各段階で削除する。
