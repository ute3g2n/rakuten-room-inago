# 出力契約

- 判断工程には実行ID、対象日、ジョブ名、入力JSONパス、出力JSONパスを渡す。担当スキルは担当工程のSchemaに適合するJSONを出力し、推測で欠測値を埋めない。
- オーケストレータは出力Schema、商品IDの存在、URLと本文の対応、重複、投稿済み除外を検証してから正本に反映する。判断工程は商品台帳、投稿管理HTML、`post-status.json`、実行台帳を直接編集しない。
- 商品のIDは全ジャンル横断で一意。異なるURLやショップでも同一商品・同一型番候補を照合する。投稿済みIDは期間が空いても再利用しない。
- 日次一覧は各商品を `ID｜商品名｜商品URL｜ジャンル｜投稿時刻｜新規投稿` で表示し、完成文の見出しに同じIDを使う。コピー用本文には管理IDを入れない。
- 確度は `✅実ページ確認`、`🔍検索結果のみ`、`💭推定`、`⚠取得失敗` を区別する。確認できない商品名、URL、価格、クーポン、セール日程を創作しない。
- 終了状態は `success`、`partial`、`action_required`、`failed`。プロセス終了コードだけで成功扱いにせず、対象日、必須成果物、Schema、保存完了を確認する。
