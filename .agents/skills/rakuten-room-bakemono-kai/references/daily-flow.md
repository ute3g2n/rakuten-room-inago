# 日次フロー

1. 対象日と実行IDを確定し、ロックと `running` マニフェストを作る。新運用開始日は2026-09-25 JST。
2. 投稿状態、商品・下書き台帳、設定、直近観測を読み、入力スナップショットを残す。
3. アフィリエイト成果、公開ROOMの直近30日いいね、在庫ブリーフをローカル工程で取得する。失敗や未取得を確認済み0へ変換しない。
4. `rr-kai-performance` の有効なJSONから勝ち条件、単一修正、優先度低下、研究要求、日次制約を得る。分析がない場合も空の有効JSONを後続へ渡す。
5. 当日分の確認済み未投稿下書きがジャンル別配分に足りなければ、研究計画とAPI候補収集を行い、最大60件の候補プールを作る。商品ページ確認は10件ずつ行い、確認済み点数の合計が6点以上（未確認項目がある場合は暫定A/B）、在庫あり、商品確認・品質確認を通った件数が不足ジャンル分そろうまで次の10件へ進む。初回トリアージの選定候補を使い切っても不足する場合は、同じトリアージの未確認候補を不確実、除外の順に補充する。未確認項目は0点扱いせず、確認済み点数を12点満点へ換算しない。上限または候補枯渇時は、確認件数と不足理由を残す。足りる場合、補充のための研究は省き、研究要求を次回キューに保存する。
6. `rr-kai-daily-plan` が15件または準備できた件数を5ジャンル6/2/2/3/2の初期配分に沿って計画する。投稿済みID、同一商品、IDとURLと本文の不一致を除外する。
7. 投稿計画、単一HTML、台帳、学習台帳を直列に確定する。本人が投稿していないチェックは変更しない。
8. ID付き一覧と不足理由、取得状況、A/B/C/保留、適用した学習条件を報告し、必須成果物を検証して終了状態を確定する。

投稿するのは本人。自動工程は本文と管理HTMLの準備まで。2026-09-24には本番投稿済み状態を書き込まない。
