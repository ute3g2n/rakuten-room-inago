# 楽天ROOM 化け物・改

ユーザーの依頼を [routing.md](references/routing.md) に従って分類し、対応する `automation/run_*.py --source chat` を起動する。実装前または入口が使えない場合は、その理由と確認できた状態を伝える。実行結果はマニフェストと検証済み成果物から報告する。

- 日次フローは [daily-flow.md](references/daily-flow.md) を読む。目標は1日15件、5ジャンル配分は6/2/2/3/2。在庫不足なら確認できた件数だけ準備する。
- 研究時の商品ページ確認は10件単位で行い、確認済み点数の合計が6点以上（未確認項目がある場合は暫定A/B）、在庫あり、商品・品質確認を通過した不足ジャンルの候補がそろうまで最大60件を確認する。初回トリアージの選定候補が尽きても不足する場合は、同じトリアージの未確認候補を不確実、除外の順に補充してページで再確認する。未確認項目を0点扱いしたり、12点満点に換算したりしない。候補枯渇・上限到達時は実数と理由を報告する。
- ショップ評価数は商品ページ内のリンクだけに依存せず、ショップコードから組み立てたショップトップを優先して確認する。取得できない場合にショップレビューURLを補助利用する。
- ID・URL・本文、確度、保存先は [output-contracts.md](references/output-contracts.md) と [data-policy.md](references/data-policy.md) を守る。
- 方法論、確度ラベル、薬機法や誇大表現の確認には `references/methodology.md` と `references/templates.md` を必要なときに読む。初期設定、診断、任意のカレンダー連携の詳細は対応する複製済みreferenceを読む。ただし旧件数、旧ジャンル、再投稿可能という記述より上記の新運用値を優先する。
- 投稿、いいね、フォロー、購入は自動実行しない。本人の投稿確認前に投稿済みにしない。楽天ID、パスワード、Cookie、Access Keyを求めたり報告に出したりしない。

最初の本番対象日は2026-09-25 JST。2026-09-24以前を新運用の未実行日として扱わない。
