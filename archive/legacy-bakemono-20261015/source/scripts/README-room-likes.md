# 楽天ROOM公開ページのいいね数巡回

`collect-room-likes.mjs` は楽天ROOMの公開商品一覧をEdge + Playwrightで読み、投稿IDごとのいいね数、コメント数、商品名、商品URL、投稿文をローカルへ保存します。ログイン情報は不要で、投稿・いいね・フォロー・コメントなどの状態を変える操作は行いません。

## 実行

```powershell
npm run room:likes:collect -- --days 30
```

ROOM URLは `rakuten-room-kai/account.md`、次に `rakuten-room/account.md` から読みます。明示する場合は次のように実行します。

```powershell
npm run room:likes:collect -- --room-url https://room.rakuten.co.jp/ROOM名/items --days 30
```

- `--days`: 1〜365。JSTの実行日を含む暦日単位で対象期間を指定。日次運用は30。
- `--max-items`: 1〜450。件数指定での診断用。`--days` とは同時に指定できない。両方省略時は30件。
- `--output-dir`: 保存先。既定値は `rakuten-room-kai/room-metrics/`。
- `--headful`: Edgeを表示して実行。

公開ページが一覧表示に使う同一オリジンの一覧応答をページ内から読み、20件を超える場合は返された次ページURLだけをたどります。`--days` では、古い投稿が混在するページがあっても期間内投稿が残っている限り巡回を続け、期間内の通常投稿が0件のページまで確認して終了します。`is_pinned` の固定投稿を除外し、ページ間の同一投稿IDは最初の観測だけを残します。最大100ページで完了しない場合は取得失敗にします。

応答のホスト、パス、投稿ID、商品URL、投稿日、いいね数を検証します。期間巡回で応答を安全に使えない場合は、全件取得を保証できないため成功扱いにせず停止します。件数指定モードだけはDOMと投稿詳細画面を読む方式へ切り替えます。

## 保存ファイル

- `latest.json`: 投稿IDごとの最新観測値。期間巡回では指定期間の現在の投稿だけへ入れ替え、対象期間と直近の期間外投稿日も保存。
- `observations.jsonl`: 初回観測または数値・内容が変わった観測だけを追記。
- `runs.jsonl`: 成功、部分失敗、取得失敗を毎回追記。
- `status.txt`: 最後の実行結果を人が読める形式で保存。

公開ページを読めない場合や値が不正な場合は、取得失敗をいいね0件として保存しません。`latest.json` の前回値も当日値として更新せず、`runs.jsonl` と `status.txt` に失敗を残します。同じ値で再実行した場合、実行履歴は残しますが観測履歴は増やしません。
