## 境界と読者

要件IR-005～007が求めるのは、実装開始前に本人が採用した5ジャンル・30テーマ、文章の型、本文長さ・タグの目安を、版と参照付きで実装担当へ渡すことです。システムへ分析処理を追加したり、本番の`settings_version`を作成したりすることではありません。IR-016はSQLiteを運用状態の唯一の正本とします。この計画のJSONは、後続の実装者が外部で確定した結果を受け取るための資料であり、運用正本や新しいDBではありません。データ辞書の`settings_version`は受領済みの外部結果を新しい設定へ登録するときの版です。`artifact`の`external_analysis_result`は受領資料の種別を示し、準備作業を実行する機能ではありません。

今回の作業ファイルは`plan/イナゴスキル事前準備/`、非公開の原観測等は作業ルート直下の`非公開作業データ/`へ分けます。原観測、他者の投稿本文全文、公開投稿者IDとの対応表はGitへ含めず、本人が実装担当へ渡せるのは匿名集計と必要最小限の参照・定義・自作例です。最終HTMLは作業成果と制約を理解するための読み物であり、機械登録の正本を置き換えません。

## 初期設定引渡しJSONの項目契約

これは実装担当向けに読める機械資料の項目案であり、実行コード、DBスキーマ、本番設定、システムへの変更ファイルではありません。実装者は列名や正規化を調整できますが、本人採用値と意味、型、親子関係は変えません。

| 項目 | 型・数 | 説明と検証 |
| --- | --- | --- |
| `artifact_kind` | 文字列 | 外部で確定した分析結果を表す識別名。準備処理を起動するモードとはしない。 |
| `version`, `status` | 文字列 | 結果資料の明示版と`proposed`／`confirmed`。45の本人回答が対象版・分類・文型・本文長さ・タグの全範囲を採用した場合だけconfirmed。 |
| `confirmed_at`, `confirmation_ref` | 時刻またはnull、参照 | 実際に得た回答時刻と本人確認記録参照。時刻が不明なら`null`と理由を記録し、記録作成時刻を回答時刻にしない。 |
| `source_requirement` | 参照 | 現行要件書の相対パス、版、章を記す。過去の基本要件承認を今回の結果採用へ流用しない。 |
| `genres` | 配列、5件 | 各要素に`genre_id`, `name`, `definition`。件数と各値を分類確定資料と直接照合する。 |
| `themes` | 配列、30件 | `theme_id`, `genre_id`, `name`, `definition`, `included_examples`, `boundary_examples`, `evidence_refs`, `material_count`, `material_kind`, `state`, `selection_count`。親ごとに6件を数える。数が不明なら`material_count: null`と理由。`selection_count: 0`は準備・運用開始前の初期値で、標本件数や選択実績ではない。 |
| `patterns`, `pattern_refs` | 配列・参照 | 観測に基づくID・構造・適用・例外、確定文型資料への参照。個数を先決めしない。因果効果の証明と扱わない。 |
| `body_length_guidance` | オブジェクト | 単位と本文の正規化規則、標本数・分布・実採用目安・対象・例外・分析参照。目安超過の保留ゲートを定義しない。 |
| `tag_guidance` | オブジェクト | タグの集計方法・母数・表示位置等の提案・実採用目安・例外・分析参照。存在しない採用値や件数を入れない。 |
| `result_index_ref` | 参照 | パス、版、生成日時、用途、状態で資料を特定する結果セット索引。 |

日時、本人回答の保存、要件参照、標本種別、版は意味の混在を避けるための引渡し情報です。絶対パス、認証情報、Cookie、公開投稿者の実名対応、入力・画像ハッシュ、画像指紋、本人以外の採用署名は引渡し項目にしません。JSON構文・必要項目・件数・参照実在を直接点検します。

## 資料間の流れ

```text
公開画面の観測（非公開作業データ）
  ├─→ 匿名の母数・分布・観測参照 ─→ 分類／文型／目安の候補
  ├─→ 原典条件台帳・レビューと修正記録
  └─→ 本人に提示した版 ─→ 本人確認記録 ─→ 採用版の初期設定引渡し
                                      └─→ 結果セット索引 ─→ 受領確認
実行記録＋上の成果と検証実績 ─────────────────→ 最終HTML
```

最終HTMLは結論と根拠種別、母数、実施範囲、レビュー実績、残る制約を本文へ書きます。HTMLを開く全ての読者に非公開の原観測が渡るような相対リンクや埋込みは作りません。実装受領のリハーサルはファイルから値を読めるかまでで、本番設定登録・日次実装・実投稿・収益確認は後続作業です。
